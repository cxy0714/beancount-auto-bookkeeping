# 回溯记账与对账（公开演示版）

本项目最初最花时间的部分，不是「记当月」，而是「补记过去月份」。
核心原则只有一句：

> 能机械算出来的，脚本算；定位到日期后，人工判断并改账。

脚本不自动填差额，不用 `pad`，不偷偷把 balance 调平。

## 1. 相关脚本

| 脚本 | 作用 |
|---|---|
| `pipeline.py` | 先为回溯账期生成标准 bean 文件 |
| `read_bank_balance.py` | 从银行 Excel 反推期初余额，并提供每日末余额 |
| `back_fund.py` | 根据下期持仓和本期交易，反推基金期初份额 |
| `restructure_main_bean.py` | 自动改写 `main.bean`：插入新 init、把旧 init 变成 balance 断言 |
| `verify_period.py` | 生成每日 balance sidecar，跑 bean-check，用 delta-jump 定位错误日期 |
| `inspect_date.py` | 精查某一天：横向打印银行/支付宝/微信/京东原始记录与 bean 分录 |
| `verify_accounts.py` | 收尾校验账户体系与 bean-check 是否干净 |

## 2. 典型工作流

```bash
# 1. 先为回溯账期生成 bean 文件
python 脚本/pipeline.py {NEW_PERIOD}

# 2. 改写 main.bean：计算期初、把旧 init 变成 balance 断言
python 脚本/restructure_main_bean.py {NEW_PERIOD}

# 3. 运行对账，输出 reports/balance_audit_{NEW_PERIOD}.md
python 脚本/verify_period.py {NEW_PERIOD}

# 4. 如果报告有错，精查具体某一天
python 脚本/inspect_date.py {NEW_PERIOD} 2025-07-15

# 5. 人工改 bean 文件后，回到第 3 步，直到全部通过
```


## 3. 三类账户的期初策略

| 账户类型 | 是否有 ground truth | 做法 |
|---|---|---|
| 银行借记卡 | 有每笔交易后余额 | 用 `read_bank_balance.py` 反推期初和外币/每日末余额 |
| 基金 | 有下期持仓 | 用 `back_fund.py` 反推期初份额 |
| 平台余额/信用卡/白条等 | 没有中间余额 | 用「下期期初 - 本期所有变化」反推，并检查资产不为负、负债不为正 |

银行账户因为 PDF/Excel 自带每笔余额，所以能做到日期级定位；
其他账户通常只能校验期末，无法定位到某一天。
## 4. delta-jump 对账算法

`verify_period.py` 的做法：

1. 给银行每个有交易的日期生成一条次日 balance 断言。
2. 给每只基金每个份额变动日生成一条份额 balance 断言。
3. 跑 beancount，收集所有 balance 错误。
4. 把错误按账户和日期排序，计算相邻差额的 jump。
5. 每个 jump 就是一个新错误点，报告里列出：
   - 日期范围
   - 差额金额
   - 当天原始账单行
   - 当天 bean 分录

这样一次运行就能把所有错误日列出来，不需要反复二分。
报告写到 `reports/balance_audit_{PERIOD}.md`。


## 5. 为什么这套东西有意思

它体现了「复式记账 + 对账 ground truth」的工程化：

- 银行流水有日级余额，可以做精确到天的差分定位。
- 基金用份额而不是价格断言，避免净值波动干扰。
- 平台余额没有中间数据，就老实承认只能校验期末。
- 脚本只做机械部分，错账判断和修正交给人。

这套思路也可以迁移到其他账本：CSV/PDF 对账、基金持仓回溯、信用卡账单核对等。
